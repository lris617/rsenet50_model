# PyTorch_nn 项目运行说明

## 1. 项目概览

`PyTorch_nn` 是一个精简后的 PyTorch 图像回归实验目录，当前主要保留了：

- 模型定义
- 训练脚本
- 测试脚本
- 两套用于快速验证的数据样例

当前项目的核心回归目标字段是：

```text
delta_vth
```

## 2. 当前实际目录结构

```text
PyTorch_nn/
├── model/
│   ├── __init__.py
│   ├── cnn.py
│   ├── cnnlstm.py
│   ├── resnet.py
│   └── vit.py
├── sample_data/
│   ├── README.md
│   ├── cnn_lstm_single_frame/
│   │   ├── train/
│   │   ├── val/
│   │   └── test/
│   └── multi_frame_sequence/

│       ├── val/
│       └── test/
├── test_cnn_lstm.py
├── train_cnn_lstm.py
├── utils.py
└── 项目运行说明.md
```

## 3. 当前可用数据

现在项目中有两套样例数据：

### 3.1 `cnn_lstm_single_frame`

结构：

```text
cnn_lstm_single_frame/
├── train/
├── val/
└── test/
```

每个 split 下包含：

```text
labels.csv
sample_*.png
```

样本数量：

- `train`：8 张
- `val`：3 张
- `test`：4 张

### 3.2 `multi_frame_sequence`

结构：

```text
multi_frame_sequence/
├── train/
├── val/
└── test/
```

每个 split 下包含：

```text
labels.csv
sample_id/
```

每个样本目录下包含 4 帧图像：

```text
combined_1.png
combined_2.png
combined_3.png
combined_4.png
```

样本数量：

- `train`：6 个序列样本
- `val`：2 个序列样本
- `test`：3 个序列样本

### 3.3 标签字段

两套数据实际依赖的关键字段都是：

```text
filename
delta_vth
```

区别在于：

- `cnn_lstm_single_frame` 中的 `filename` 形如 `sample_055.png`
- `multi_frame_sequence` 中的 `filename` 形如 `14_055`

## 4. 当前脚本和数据的对应关系

这是现在最重要的一点。

### 4.1 当前 `train_cnn_lstm.py` / `test_cnn_lstm.py`

从当前代码实现看：

```python
seq_len = 1
img_path = os.path.join(self.root_dir, f"{sample_id}.png")
```

这说明当前脚本实际是按“单张图片路径”读数据，而不是按“样本目录 + 4 帧”读数据。

所以当前脚本真正匹配的是：

```text
PyTorch_nn/sample_data/cnn_lstm_single_frame/
```

而不是：

```text
PyTorch_nn/sample_data/multi_frame_sequence/
```

### 4.2 `multi_frame_sequence` 的定位

这套数据适合真实的多帧 CNN-LSTM 数据加载逻辑，但和当前保留下来的 `train_cnn_lstm.py` / `test_cnn_lstm.py` 并不直接匹配。

换句话说：

1. 它是正确的多帧样例数据。
2. 但当前脚本还没有按这个目录格式去读取。

## 5. 训练脚本

入口：

```bash
python PyTorch_nn/train_cnn_lstm.py
```

### 5.1 当前默认参数

脚本中写死的主要参数如下：

```text
batch_size = 16
seq_len = 1
img_size = 224
num_epochs = 1500
lr = 1e-4
cnn_type = "resnet50"
feature_dim = 1
lstm_hidden_dim = 256
lstm_layers = 1
```

### 5.2 当前默认数据路径

代码里目前仍然写着旧路径：

```text
PyTorch_nn/dataset14/train
PyTorch_nn/dataset14/val
```

这些目录当前已经不存在。

如果你要按当前代码直接跑，建议改成：

```python
train_img_dir = "PyTorch_nn/sample_data/cnn_lstm_single_frame/train"
train_label_csv = os.path.join(train_img_dir, "labels.csv")
val_img_dir = "PyTorch_nn/sample_data/cnn_lstm_single_frame/val"
val_label_csv = os.path.join(val_img_dir, "labels.csv")
```

### 5.3 当前默认权重路径

脚本里还写着：

```text
PyTorch_nn/report/resnet50_peak2peak_best_epoch1472_val0.0023.pth
```

这个文件在当前精简后的目录中并不存在。

如果只是想跑通流程，可以：

1. 把 `resnet_weights_path` 改成 `None`
2. 或换成你当前真实存在的 `.pth` 文件

### 5.4 小样本验证建议

由于当前样本很少，建议先把：

```python
num_epochs = 1
```

## 6. 测试脚本

入口：

```bash
python PyTorch_nn/test_cnn_lstm.py
```

### 6.1 当前默认测试路径

代码里目前写的是：

```text
PyTorch_nn/dataset14/test
```

这个目录当前不存在。

如果按当前代码直接跑，建议改成：

```python
test_img_dir = "PyTorch_nn/sample_data/cnn_lstm_single_frame/test"
test_label_csv = os.path.join(test_img_dir, "labels.csv")
```

### 6.2 当前默认模型目录

测试脚本会默认去这里找模型：

```text
report/cnnlstm14.12/cnnlstm/resnet50_bs16_lr0.0001_feature1_lstm_layers1_hiddendim256
```

并匹配：

```text
cnn_lstm_best_epoch*_val*.pth
```

如果训练输出目录改了，`model_save_dir` 也要一起改。

## 7. 推荐运行方式

建议始终从仓库根目录运行：

```bash
cd D:\rsenet50_model
python PyTorch_nn/train_cnn_lstm.py
python PyTorch_nn/test_cnn_lstm.py
```

## 8. 当前最重要的注意事项

### 8.1 现在有两套样例数据，但当前脚本只匹配其中一套

当前直接能配合现有脚本运行的是：

```text
cnn_lstm_single_frame
```

`multi_frame_sequence` 目前是为真实多帧加载逻辑准备的样例数据。

### 8.2 文档已更新，但脚本默认路径还没同步

代码里仍然保留了这些旧路径：

- `PyTorch_nn/dataset14/...`
- `PyTorch_nn/report/...`
- `report/cnnlstm14.12/...`

所以实际运行前，仍然需要先改路径。

### 8.3 当前仓库没有旧的大数据目录

当前仓库中已经没有这些旧目录：

- `dataset/`
- `dataset14/`
- `dataset4lstm14/`
- `report/`

## 9. 当前最简可执行流程

如果你只是想快速检查当前代码能不能跑通：

1. 把训练路径改到 `PyTorch_nn/sample_data/cnn_lstm_single_frame/train` 和 `val`
2. 把测试路径改到 `PyTorch_nn/sample_data/cnn_lstm_single_frame/test`
3. 把预训练权重路径改成 `None` 或有效路径
4. 把 `num_epochs` 临时改成 `1`
5. 再运行训练和测试脚本

## 10. 后续建议

如果你接下来继续整理项目，建议优先做这几件事：

1. 把 `train_cnn_lstm.py` / `test_cnn_lstm.py` 的默认路径改成当前样例目录
2. 如果你准备使用 `multi_frame_sequence`，那就把数据加载逻辑改成按样本目录读取 `combined_1.png` 到 `combined_4.png`
3. 把权重路径改成配置项，不要写死在代码里
